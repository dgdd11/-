# Практична робота №1

**Дисципліна:** Аналіз програмного забезпечення.  
**Студент:** Слуцьковський Данііл Андрійович, група 121-23-2.

## Тема та мета

Підписання персонального документа за допомогою кваліфікованого електронного підпису. Мета - навчитися створювати PDF, накладати КЕП та перевіряти результат.

## Хід роботи

1. Підготовлено [PDF із фактами про себе](document.pdf): ім’я, університет, група та навчальний проєкт Life RPG.
2. Для підписання обрано Дія.Підпис.
3. Отримано підписаний контейнер `Документ для підписання Слуцьковський.pdf.asice`.
4. Під час перевірки структури контейнера знайдено вихідний PDF, `mimetype`, маніфест і XML-файл підпису. Вкладений PDF збігався з підготовленим оригіналом.

Структурна перевірка контейнера не замінює криптографічну перевірку КЕП. Протокол перевірки ЦЗО до цих публічних матеріалів не додано. Підписаний контейнер зберігається окремо; до репозиторію включено вихідний PDF.

## Контрольні питання

**Що таке КЕП?** Кваліфікований електронний підпис створюється кваліфікованим засобом і базується на кваліфікованому сертифікаті відкритого ключа. Він дає змогу встановити підписувача та перевірити цілісність підписаних даних.

**Навіщо використовують КЕП?** Для дистанційного підписання електронних документів, ідентифікації підписувача та виявлення змін у підписаному вмісті.

**Які сервіси використовують?** КНЕДП «Дія», АЦСК ПриватБанку та інші кваліфіковані надавачі. Для накладення підпису потрібен сервіс, сумісний із наявним ключем.

**Як перевірити підпис?** Відкрити підписаний файл у сервісі перевірки, переглянути результат, дані підписувача та сертифіката. Для відокремленого підпису може знадобитися оригінальний документ.
